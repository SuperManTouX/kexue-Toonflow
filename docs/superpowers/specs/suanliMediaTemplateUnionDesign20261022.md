# SXWZ 媒体模型模板并集与图片上传设计

**状态：已批准**

**日期：2026-10-22**

## 目标

统一支持 SXWZ 当前媒体模型参数模板中出现的控件，让图片、视频和音频节点按模型模板编辑并提交参数。模板的静态类型、运行时校验和参数表单采用当前模型模板的并集，避免某一个模型的控件遗漏导致模板被误判为无效。

支持包含 `imageUpload` 的模板：素材仍留在 Toonflow 本地工作区，由本机 Server 读取后以 Data URL（`data:<mime>;base64,...`）填入上游模板字段并发送给 SXWZ。应用不配置 OSS 凭据，也不把本机路径交给 SXWZ。

## 范围

- 扩充媒体参数的共享 TypeScript 联合类型、Server Zod schema、表单渲染和任务参数校验，使其覆盖已获取到的媒体模板控件；新增确认过的 `ui: "number"`，并支持 `min`、`max`、`default`、`required`、`showWhen` 等模板字段。
- `showWhen` 依据同一模板中已提交的字段值控制条件参数的显示；隐藏字段不渲染，不接受浏览器绕过表单直接提交隐藏值。
- 对 `imageUpload` 参数，将节点已有的本地图片引用绑定到模板参数；服务端从当前工作区读取并转换为 Data URL，再按模板字段要求组装任务 `body`。
- 对纯文本、选择项、数量、尺寸、开关及其他当前模板出现的控件，继续按模板定义校验、展示和序列化；不把所有非特殊字段都当作带 `options` 的选择项。
- 保留现有模型目录、平台/类别过滤、任务轮询和结果保存路径。

本文的 Data URL 方案取代 `desktopSxwzMediaDesign20261021.md` 中“缺少远程上传方式时，带 `imageUpload` 的模板不可用”的阶段性决定；旧规格的其余边界不变。

## 数据与信任边界

参数模板由 SXWZ 模型配置接口读取。客户端只能提交模型引用、普通控件值和工作区相对路径形式的已有素材引用；Server 必须重新从可信模型目录和模板取得模型/平台归属及参数定义，不能信任客户端提交的 Data URL、任意 URL、MIME、文件大小或模板副本。

本机 Server 在当前工作区边界内解析每个文件引用，拒绝越界路径、目录、不可读文件、非图片文件及不满足模板数量或体积限制的素材。单文件体积同时受模板 `maxSizeMB`（存在时）和应用现有 100 MiB 文件上限约束；所有图片编码前完成校验，避免无界内存扩张。`maxCount`、`maxImages` 等限制按模板定义执行。

图片上传字段按字段名和模板语义映射到节点已有素材。用户确认 `imageUrls` 通常接受 Base64；因此唯一通用映射是单个 `ui: "imageUpload"` 的 `imageUrls` 字段接收本地图片 Data URL 数组，并且仍须核对模板与所选 `modelRef` 一致。字段使用其他名称、同一模板包含多个上传字段或值形状不符时，在本机返回包含字段路径的校验错误，不静默丢弃图片，也不猜测别名。缺少必需素材或数量超限时同样在上游调用前失败。

媒体模型目录由受支持源平台中符合媒体类别的模型组成；源平台编码保留在 `modelRef` 和模板归属检查中，媒体任务请求使用 `platform_code: "toonflow"`。

Base64 仅在本次服务端上游请求生命周期内存在：不写画布、设置、任务持久化记录或请求日志。可持久化的模板诊断保留 `modelRef`、`modelId`、上游 `code` 及字段级校验路径/类型；SXWZ Token、Authorization、完整 hidden default 和图片 Data URL 不落日志。

## 参数表单与兼容规则

- 前端表单按控件类型渲染字段，显示模板默认值和边界；Server 使用相同模板规则校验浏览器传来的值，并按模板声明的字段名生成上游参数。
- 条件字段依赖的字段值变化后，表单及服务端校验使用同一 `showWhen` 规则；条件不满足时忽略该字段，不把其隐藏值发给上游。
- `number` 按有限数值校验，并应用模板声明的 `min`/`max`；未声明范围时不虚构边界。`required`、选择项及默认值均由 Server 校验，不能只依赖浏览器控件。
- `imageUpload` 值由 Server 从工作区素材生成，客户端参数不能覆盖该值。为避免请求体超出限制，Data URL 总量也受现有 HTTP 请求体上限约束；超限时在上游调用前明确失败。
- 未知控件类型或缺少必要结构的配置作为模板校验错误返回并记录字段路径，不以“模型归属无效”混淆真实原因，不向上游发送部分参数。

## 已知上游样本与限制

- 实时模板扫描得到 13 个 SXWZ 媒体模型：10 个模板可解析；Flux 和 LTX 2.3 T2V 因缺少 `number` 控件支持被当前实现拒绝。实查模板中，Flux 的 `customWidth`、`customHight` 范围为 256–1536，默认值为 1024，且仅在 `aspectRatio` 为 `custom` 时显示；LTX 2.3 T2V 的 `duration` 范围为 5–15，默认值为 5。
- Vidu q3 首尾帧模型的上游配置请求返回 `code: 1` 且没有 `data`，这是上游配置不可用，不属于本地模板 schema 错误；界面与日志应保留可诊断的上游错误。
- 用户授权的单次合成图片探测已验证 Banana-Pro 的 `imageUrls` 数组可以接受 Data URL，任务已完成；用户补充该字段通常接受 Base64。实现仅通用支持唯一的 `imageUrls` 上传数组，其他字段名和多字段模板仍失败关闭。
- 新增控件支持后，重新只读检查当前可访问的全部 SXWZ 媒体模板，区分本地解析/归属错误与上游返回失败；不为验证而额外提交生成任务。

## 验收标准

1. 共享联合类型、Server 运行时 schema、参数表单和任务校验均覆盖所有当前成功读取且结构有效的模型模板；Flux 与 LTX 2.3 T2V 的已知 `number` 模板可正确解析、显示、校验条件值并组装参数。
2. 所有模板中的条件字段按 `showWhen` 一致显示和校验；无效默认值、越界数值、非法选项和不满足 required 的参数在提交上游前失败。
3. 当前成功读取且结构有效、且唯一上传字段为 `imageUrls` 的模板都可把节点已有的本地工作区图片转换成 Data URL 数组并由 Server 提交；其他字段形状不被误判为可用；素材缺失、非法、超数或超体积时明确失败。
4. Server 不接受客户端提供的任意远程 URL、Data URL 或路径越界文件；生成链路不要求 OSS 配置或共享上传密钥。
5. Data URL、SXWZ 凭证及完整 hidden default 不进入持久化文件和日志；日志仍足以定位模型归属、上游响应码、模板字段路径及校验类型。
6. 上游返回失败或模板无效时不发起任务；Vidu q3 当前无配置数据时显示为上游配置失败，而不是伪装成已支持模板。
7. 不新增测试/自检文件、测试依赖或脚本。实现后的验证按仓库规范执行现有 typecheck/build 和只读模板检查，不再额外产生计费任务。

## 非目标

- OSS、公网对象存储、上传凭据发放或把素材上传到 SXWZ 之外的服务。
- 修改模型目录授权规则、任务计费/轮询/取消语义、工作区保存方式或 SXWZ 登录流程。
- 为上游 `code: 1` 且缺少配置数据的模型猜测参数 schema。
