# Web 多用户隔离与 SXWZ 登录设计

状态：Web 用户隔离已实现；构建及临时 HTTP 验证已执行，真实 SXWZ 登录和双账号隔离仍待可用账号验证。日期：2026-10-17。

## 目标与范围

同一个 Web 服务供多个用户使用。登录身份来自 SXWZ；用户只能访问自己的项目、画布、文件、素材、设置、API Key、个性化文档和 Agent 对话。运行中的任务、回调与事件订阅也必须校验用户归属。

本次仅涉及 Web 端及其服务端。沿用 Bun、Express、TypeScript、单进程服务和现有文件持久化方式。不新增账号密码、注册、管理后台、组织权限或协作分享。桌面和移动端不在本次范围，其入口、目录布局及既有数据行为保持原样。下述旧数据弃用、登录和隔离要求只适用于 Web 服务模式。

## 已核对的现状

- `apps/server/src/app.ts` 装配 Web、API、MCP 和 A2A；没有统一的应用用户认证。
- `utils/conf/index.ts` 创建全局配置，设置和供应商密钥混存在同一份 `settings.json`。
- 工作区校验限制在共同的 `data/workspaces` 下，没有用户归属。
- 素材、记忆、技能等根据配置文件所在目录定位；插件目录有模块加载时计算的常量。
- 临时 Agent、控制连接等保存于进程级 Map，部分操作只按客户端提供的 ID 查找。
- 前端先加载设置再挂载应用；持久化入口还会回退读取旧的 localStorage。
- 工具插件是可信服务端代码，不在沙箱中；媒体供应商还有接收源码并运行的调试接口。
- TF-Router 登录用于配置模型 API Key，不能代替应用用户认证。

## 方案选择

采用单进程内的可信用户上下文、用户目录和运行状态归属校验。复用现有文件能力，控制本次改动范围。

备选方案是将用户、设置和业务资源全部迁移至数据库。它适合后续复杂检索和协作授权，但仍须处理当前文件工作区与内存任务的归属，本次不增加这套持久化迁移。

不通过修改全局环境变量、全局“当前用户”或请求携带的目录来切换身份。

## 登录与本地会话

1. 外部平台通过独立的 `/token-login` 路由引导登录，并将 `externaltoken` 放入 Vue Router query（Hash 模式示例：`/#/token-login?externaltoken=...`）。只有该路由会触发外部登录；前端在业务初始化、设置读取及统计启动前取得参数，并立即从地址栏移除。也兼容 `/token-login?externaltoken=...` 页面外层 query。后端登录接口供前端提交外部 Token。
2. `POST /api/auth/login` 接收 `{ sxwzToken: string }`，使用现有 Zod 中间件校验非空及长度上限；只接受同源页面请求，限制登录尝试频率。
3. 后端向环境变量 `EXTERNAL_TOKEN_VERIFICATION_URL` 指定的完整地址发送 POST，请求体为 `{}`，Authorization 使用外部 Bearer Token，超时为 10 秒，禁止自动跟随重定向。生产仅接受 HTTPS。
4. 严格要求 HTTP 200、JSON 数字 `status === 1000`、非空字符串 `data.userInfo.userName` 和 `data.userInfo.sessionId`。接口契约依据本次提供的 `sxwz-token-login` 技能；不猜测其他响应结构。
5. 按 `(sxwz, sessionId)` 对应的身份摘要查找本地绑定。摘要采用服务端持久化随机密钥计算；本地用户 ID 由服务端随机生成。显示名变化不改变身份，不按同名用户合并。这里依赖提供方将 `sessionId` 作为稳定外部身份的契约。
6. 无绑定时自动建立普通用户，不赋予管理权限。首次绑定的读取、判断、写入在同一进程内串行完成，使用原子写入避免并发重复建档。
7. 签发随机的本地会话凭证；服务端仅保存凭证摘要、用户 ID 和到期时间。Cookie 使用 `HttpOnly`、`SameSite=Lax`、`Path=/`，生产使用 `Secure`，固定有效期 7 天，不新增 refresh 机制。
8. `GET /api/auth/get` 返回本地用户 ID、显示名与运行模式；不返回外部身份字段或凭证。`POST /api/auth/logout` 撤销当前会话、关闭该会话建立的订阅并清除 Cookie。

原始 SXWZ Token 验证后即丢弃，不存入设置、本地会话或日志。本次不代表用户调用其他 SXWZ 业务接口。

验证失败返回 401；上游超时或不可用返回 502/504；未配置验证地址使 Web 多用户模式启动失败。任何情况均不回退到匿名用户、客户端身份或共享配置。

## 数据布局与统一入口

```text
data/
  auth/
    identityKey
    identities.json
    sessions.json
  users/
    <本地用户ID>/
      settings.json
      workspaces/
      assets/
      memories/
      skills/
      ai/
      singleAgent/
      AGENTS.md
  shared/
    tools/
    nodes/
    ext/
    providers/
    agents/
    ffmpeg/
```

身份、会话及密钥文件仅供服务端访问，权限为 0600；用户数据目录限制为服务进程可访问。身份快照和会话快照通过 `@toonflow/file` 原子写入；密钥首次创建使用 exclusive，不能覆盖既有密钥。

`TOONFLOW_DATA_DIR` 始终表示整个服务的数据根目录。用户目录由服务端本地用户 ID 推导，不能来自客户端路径、Token 原文、显示名或外部 sessionId。

配置仍在 `utils/conf` 集中初始化和管理；每个用户复用自己的配置实例，接口不重复创建实例，完整覆盖保存的语义保持不变。启动配置与共享资源根目录和用户配置显式区分。

认证中间件建立异步请求上下文。用户级配置和路径入口在每次操作时读取可信上下文；异步任务创建时捕获用户与目录快照。不存在用户上下文时，用户业务入口直接报错。禁止隐式回退全局配置。

本次随版本发布或由部署者明确安装的工具、节点、扩展、供应商与团队作为受信任资源共享读取，初始化到新的 `data/shared`，不扫描旧安装目录或复用其中的副本。用户的密钥、模型选择、配置、启用状态和可编辑业务数据分别保存。需要按用户刷新或编辑的供应商模型列表保存为用户数据，不改写共享代码文件。共享技能仅作为模板，用户可编辑副本写入自己的目录。

## 请求授权与文件边界

- 独立 Web 服务默认启用 SXWZ 多用户认证；`createApp` 明确区分 Web 多用户模式与原生宿主的本地模式。模式只由服务端启动配置决定。
- 静态前端和必要的认证入口公开；其余业务 API 统一鉴权。未登录返回 401。
- Web 模式不接受“本机地址”“Origin 相同”或 `x-toonflow-workspace` 作为身份；反向代理不能绕过认证。
- 工作区的目录枚举、校验和所有读写入口均限于当前用户的 `workspaces`。保留现有 realpath、路径穿越、符号链接、冲突保护和原子保存规则。
- 资产、个性化文档、技能、附件上传缓存及临时对话目录均使用当前用户根目录。
- 用户不能通过工作区文件接口读写用户根目录本身、认证存储或共享插件目录。
- 对跨用户资源统一返回 403 或不存在，不泄露资源内容；不因 ID 难猜而省略归属校验。
- Cookie 写操作校验同源 Origin/Referer 与既有页面请求标记，不使用开放 CORS 携带会话。
- 多用户模式下的客户端请求携带当前页面绑定的本地用户 ID 用于会话一致性检查。它不参与认证或决定数据范围；与会话用户不一致时拒绝请求，避免另一标签页换号后将旧页面数据保存到新用户。

## 运行状态与外部协议

- 临时 Agent、任务、问答回调、画布回调、控制连接和余额事件订阅记录用户归属；读取、控制、回答、取消和订阅均核对当前用户。
- 已经按绝对路径索引的会话继续复用，但所有入口先证明路径属于当前用户。凭 ID 查找的记录增加用户归属。
- 用户相关的模型初始化、失效控制器、余额和报价缓存按用户划分；同名供应商或相同密钥不使不同用户共享可订阅的状态。
- MCP 和 A2A 的服务凭证必须在服务端解析为本地用户，再进入同一用户上下文。只允许使用当前用户的控制连接、工作区和配置；不能由工具参数指定身份。
- MCP/A2A Bearer 只用于对应协议入口，不能直接请求普通 `/api`。MCP 调用同进程 API 时使用服务端生成的短时签名，签名绑定用户、方法、完整目标和请求体，并拒绝重放。
- MCP/A2A 凭证与本地浏览器会话分开管理，凭证摘要唯一绑定用户；重复绑定其他用户的凭证必须拒绝。退出网页仅撤销网页会话，既有独立服务凭证按各自的显式关闭或轮换动作撤销。
- Web 多用户模式使用主服务的 MCP/A2A 路径，不允许用户配置额外监听端口或操作其他用户的运行时；原生宿主保留现有本机 MCP 方式。

## 必须收紧的共享能力

用户可配置自己的 API Key 和业务选项，但不能通过 Web 安装、替换、删除或调试运行任意服务端插件、供应商及团队代码。共享可执行资源由部署者在服务器侧安装。

多用户模式需在服务端拒绝这些入口，并在前端隐藏对应操作。包括源码调试运行、源码安装、本机文件选择及读取、宿主更新、进程级设备互联管理，以及修改 FFmpeg 可执行程序路径等能改变宿主执行行为的设置。FFmpeg 可执行程序虽由部署者配置，但 Fluent API 参数、filter 和清单仍可触发工作区之外的间接文件或网络 I/O；在提供操作系统级沙箱前，Web 多用户模式只允许无参数探测，拒绝实际 FFmpeg 任务。Web 服务也不启动桌面设备互联进程。

这是当前插件直接执行于服务进程这一实际边界所要求的限制。本次不提供第三方不可信代码沙箱。

## 前端初始化与退出

前端先完成 URL Token 处理和本地会话确认，再读取设置、创建持久化 Store、挂载项目页面。无会话时显示从 SXWZ 进入的提示或实际登录错误，不增加账号密码表单。

用户设置和项目列表从已鉴权的设置接口加载。Web 模式不执行旧 localStorage 导入、旧配置迁移和旧引导状态恢复，从新数据开始；原生模式的既有行为不在本次改动范围。

退出或切换用户时停止自动保存队列、在途请求、SSE 和控制连接，销毁当前用户内存状态后重新初始化页面。队列内的多步保存绑定原用户，不随 Cookie 或当前项目变化切换目标。

前端使用既有 Axios、fetch、工作区文件入口及插件宿主请求接口，逐一覆盖 JSON、二进制上传、图片视频读取和流式请求；同源 HttpOnly Cookie 统一用于浏览器认证。

## 旧数据处理

用户已明确 Web 端所有旧数据都抛弃。Web 旧设置、API Key、项目、画布、文件、素材、记忆、对话、技能、插件安装副本和浏览器缓存均不迁移、不导入、不自动认领、不作为默认数据，也不提供旧路径的回退兼容。此要求不扩展到桌面或移动平台。

新用户从独立目录及当前版本不含用户密钥的默认设置开始。用户隔离实现不添加迁移工具，也不为旧数据保留兼容分支。

旧文件不会被实现自动迁移、读取或回退使用；现存磁盘文件保留原样，本次不执行物理删除。

## 验证与交付边界

遵守仓库规范，不新增测试、自检、mock 或 fixture 文件，不新增测试命令、测试依赖或 CI 测试入口。

接口变更后执行现有 `bun run routes`，再执行 server/web 类型检查及相关构建。必要手动 HTTP 验证使用临时数据目录，覆盖未登录拦截、非法输入、会话失效和跨用户目录/资源拒绝；不覆盖真实用户配置。

SXWZ 真实登录及两个真实账号之间的完整隔离，需要有效的外部登录凭证和可用上游。未完成这些验证时，交付报告明确标注未验证，不以编译或构建通过代替功能验证，也不通过实际计费生成验证登录。

本方案只支持现有单进程模型，不声称支持多个实例同时写同一数据目录。没有不可信代码沙箱，也不自动配置反向代理日志；部署说明应指出查询 Token 的访问日志脱敏要求。
